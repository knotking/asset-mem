# HomeApp Frontend Guide

This repository hosts two client-facing applications that sit on top of the HomeApp platform:

- `apps/webapp`: the responsive Next.js experience served to desktop browsers.
- `apps/mapp`: the Expo / React Native application distributed to mobile devices (iOS, Android, web preview).

Both clients depend on the shared `apps/common` package for contexts, design primitives, and TypeScript
contracts. This guide walks through environment preparation, configuration, and day-to-day workflows for
running each app locally.

---

## 1. Prerequisites

- **Node.js 20.x** (aligns with Next.js 15 + Expo SDK 49 requirements). Use `nvm` or `asdf` to manage versions.
- **npm** (ships with Node). Yarn and pnpm are not required; the workspaces ship with lockfiles generated by npm.
- **Expo tooling** for mobile development:
  - `npm install --global expo-cli`
  - iOS: Xcode + simulators (macOS only)
  - Android: Android Studio + an emulator or a physical device with USB debugging enabled
- **Firebase project access** with credentials for development and staging environments.
- **Proxy / agent backend** reachable via the URLs exposed in the `.env` files (see below).

> ℹ️ HomeApp developers typically keep a `.env` file per app with the Firebase config, proxy URLs, and Gemini
> agent endpoints. See `apps/mapp/docs/ENV_CONFIG.md` for the full variable matrix.

---

## 2. Project Layout

```
apps/
├── common/        ← Shared UI primitives, contexts, and typing
├── mapp/          ← Expo application
└── webapp/        ← Next.js application
```

- Install dependencies at the app level. `apps/common` exports a package consumed by both clients.
- Run scripts from each app directory; there is no top-level monorepo script façade.

---

## 3. Shared Setup Steps

1. **Install dependencies**

   ```bash
   cd apps/common && npm install
   cd ../webapp && npm install
   cd ../mapp && npm install
   ```

   > Installing `apps/common` first ensures the local package is linked before the other apps resolve it.

2. **Configure environment variables**

   - Copy the provided sample env files (if present) or create new ones based on `apps/mapp/docs/ENV_CONFIG.md`.
   - Typical locations:
     - `apps/webapp/.env.local`
     - `apps/mapp/.env`
     - `apps/common/.env` *(only needed for Firebase emulator helpers or storybook previews)*
   - At minimum you will need:
     - Firebase project keys (`NEXT_PUBLIC_FIREBASE_*`, `EXPO_PUBLIC_FIREBASE_*`)
     - Proxy base URL for the AI agent (`PROXY_BASE_URL` / `NEXT_PUBLIC_API_BASE_URL`)
     - Gemini / Vertex configuration where applicable (`GOOGLE_CLOUD_PROJECT`, `GOOGLE_CLOUD_LOCATION`)

3. **Start supporting services**

   - Ensure the GCP proxy (`gcp/proxy`) is running against the same environment your app points to.
   - If using the Firebase emulator suite, start it before launching either client.

## 4. Running the Web App (`apps/webapp`)

### 4.1 Development server

```bash
cd apps/webapp
npm run dev
```

- The Next.js server listens on `http://localhost:9002` (see `package.json`).
- Hot reloading is enabled via Turbopack.

### 4.2 Building for production

```bash
npm run build
npm start
```

- `npm run build` compiles the Next.js app for production.
- `npm start` serves the compiled output. Useful for staging verification against the deployed proxy.

### 4.3 Linting and type checks

```bash
npm run lint
npm run typecheck
```

> Tip: run `npm run genkit:dev` in a separate terminal when working on AI flows inside `src/ai`.

## 5. Running the Mobile App (`apps/mapp`)

### 5.1 Expo development workflow

```bash
cd apps/mapp
npm run dev
```

- Launches the Expo dev server, clears caches (`-c`), and shows the QR code.
- Press `i` for iOS Simulator, `a` for Android Emulator, or scan with the Expo Go app on a physical device.

Alternate platform-specific shortcuts:

```bash
npm run ios     # Expo dev server + iOS simulator
npm run android # Expo dev server + Android emulator
npm run web     # Expo dev server + React DOM preview
```

### 5.2 Environment notes

- Expo reads config from `app.config.js`, which merges `.env` variables. Confirm `PROXY_BASE_URL` resolves to a reachable backend; otherwise triage and session creation will fail.
- To override the default Firebase project for local testing, set `EXPO_PUBLIC_FIREBASE_PROJECT_ID` and friends in
  `.env`.
- The mobile app assumes the shared `@homeapp/common` package is built in place. Reinstall or re-run
  `npm install` after changing shared code.

### 5.3 Debugging tips

- Use `Expo Router` dev tools (`press d`) to inspect routes, logs, and network requests.
- The chat screen writes verbose logs to Metro. Filter for `[PropertyDetails]` or `streamAgentResponse` to trace
  messages reaching the backend.
- For attachment uploads, ensure the Firestore storage bucket configured via env variables is accessible from the
  current Firebase credential.

## 6. Common Tasks

- **Linking Firebase Auth & Firestore:** both apps expect the user to authenticate; ensure the web and mobile clients
  point to the same Firebase project or emulator suite to share sessions.
- **Triaging issues:** if the triage agent appears unresponsive, verify that the proxy is reachable and that the
  request payload contains `user_id`, `session_id`, and `user_query`. The mobile and web clients send identical
  payloads to the `/firebase-agent-stream` endpoint.
- **Updating shared UI:** modify components in `apps/common`, then rebuild or reinstall dependencies in each client.
